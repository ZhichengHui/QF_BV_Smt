## The rule

The `ccount` of a definition is that of `proof/QFBV_Bound.thy:842`: the sum of `ncost` over its
subterms. `bcost` is computed on the width of the first operand: `And/Or/Xor` 5w, `Add` 15w,
**`Mul` 19·w·w**, `Udiv/Urem` 76w²+92w+14, `Shl/Lshr` 5w·nst(w)+9w, `Concat` 0, `Eq` 9w, `Ult`
15w; `Ite` adds 5w. In Rust these are `bcost` and `term_ccount`. They saturate at `cap()` = 2^63
(`sat_add`, `sat_mul`), and `nst` is the existing `stages`.

`normalize q = normalize_k q 2`. `normalize_k q f` keeps two counters, `seen` and `spent`. Before
old definition `j` is processed, `seen += ccount(q.defs[j])` (with the widths of `q`). The
definitions that the substitution of `v = t` drops are skipped; they are `Var(v)`, of
`ccount` 0, so this changes nothing. Then
`room = (f−1)·seen − spent` (0 if negative). In `mk`, a product `r` with `n > 2` factors
(`product_factors`, cap 16) is flattened only if `w > 0` and `extra = 19·w·w·(n−2) ≤ room`. In
that case `spent += extra`. Otherwise `r` stays one definition, `Mul(Ref, Ref)`, which is still
shared through `mk_raw`. `extra` is charged in full even when `mk_raw` finds some links of the
chain already defined.

**`distribute` needs no budget.** It replaces the product `a·(x+y)` by the sum `p + q` only when
both products `p` and `q` already exist (`lookup`). So it adds at most one definition, an `Add`
of cost 15w, in place of the `Mul` of cost 19w². The bound below covers it as a non-flattening
step.

## Paper argument (for whoever extends `normalize_m` and proves `fb_hyps q'`)

Let `C_j = ccount(q.defs[j])`, `S_j = C_0 + … + C_j`, and let `X_j` be `spent` after step `j`.

1. **Invariant `X_j ≤ (f−1)·S_j`.** If step `j` flattens, then `X_j = X_{j−1} + e_j` and
   `e_j ≤ (f−1)·S_j − X_{j−1}`. Otherwise `X_j = X_{j−1} ≤ (f−1)·S_{j−1} ≤ (f−1)·S_j`. (Under
   `fb_hyps q`, `S < 2^56`, so nothing saturates. If it did saturate, `fb_hyps q` would already
   fail.)
2. **What step `j` adds to `q'`.** This uses the invariant of `normalize_m` that `map` preserves
   widths (`widths'[map k] = dw[k]`), so `remap` preserves `ccount`.
   - Substituted variable (`sb[v] < j`): nothing.
   - Not flattened: at most one new definition, `r`, with `ccount r ≤ C_j`. Either `r` is
     `remap(q.defs[j])` (cost equal), or a rewrite of it: `Eq(a,a)` and `x + ¬x` become `Const`
     (0); `x · ones` becomes `cneg x = Add(Not(Ref), Const)`, cost 15w ≤ 19w², with `w > 0`
     checked; `distribute` gives `Add(Ref, Ref)`, cost 15w ≤ 19w².
   - Flattened: here `r` is `remap(q.defs[j]) = Mul(Ref, Ref)` of width `w`, because the rewrites
     and `distribute` return a non-product whenever they change the term. So `C_j = 19w²`. All
     `n` factors have width `w`, since `Mul` operands have equal widths and this holds through the
     chain. The chain adds at most `n−1` definitions `Mul(Ref, Ref)` of width `w`, together at
     most `(n−1)·19w² = C_j + e_j`.
3. **`Σccount(q') ≤ Σ_j C_j + X_{last} ≤ f·Σccount(q)`**, which is `≤ 2·Σccount(q)` for the
   shipped `f = 2`. The assertions are `remap`s and keep their `ccount`. Definitions found by
   `mk_raw` add nothing.
4. **Definition count.** Step `j` adds at most one definition beyond those it charges, and a
   flattening charges `19w² ≥ 19` per extra product (`w ≥ 1`). So
   `|defs q'| ≤ |defs q| + X/19 ≤ |defs q| + (f−1)·Σccount(q)/19`, and with `Σccount(q) < 2^56`
   this is `< |defs q| + 2^52` (f = 2) or `< |defs q| + 2^53` (f = 3). Both fit the ~8× slack
   that `fb_hyps` leaves for the number of definitions.

For `normalize_m` this means one extra argument, `f` (or the constant 2), and two `nat` counters
in the fold state, `seen` and `spent`. The flattening branch also gets the guard
`w > 0 ∧ 19·w²·(n−2) ≤ (f−1)·seen − spent`. Both arms already prove model equivalence, so the
guard changes nothing there.

and a chain `t_k = a_{16−k} · t_{k−1}` of 15 products of width 32, whose sorted chains share no
prefix. `normalize_k` gives 15 products with f = 1 (no flattening), **18 with f = 2, 33 with
