## What it holds

- Models, statement by statement: `luby_up` (up loop), `luby_down` (down loop), `luby_m`
  (`1 << seq` = `2 ^ seq`). Rust's `size` is `sz` (`size` is a HOL constant). `.simps` are
  `[simp del]`.
- `luby_down` has the extra guard `0 < sz` (not in the code) only so that the model terminates on
  `nat`; `down_inv_pos` shows it always holds in reachable states.
- Up loop: invariant `up_inv` (`sz = 2^(seq+1) - 1`, `sz ≤ 2i+1`), `up_inv_init`, `up_inv_step`,
  `up_inv_no_overflow` / `up_step_no_overflow` (for `i < 2^63`: `i + 1`, `sz`, `2 * sz + 1` below
  `2^64`, `seq < 64`), `luby_up_result` (`sz = 2^(seq+1)-1`, `i+1 ≤ sz ≤ 2i+1`).
- Down loop: invariant `down_inv` (adds `x < sz`, `x ≤ i`), `down_inv_step` (when the loop goes on:
  `1 < sz`, `0 < seq` — no underflow of `sz - 1`, `seq - 1` —, new `sz > 0` — no division by zero —,
  invariant kept), `luby_down_inv` (end: `x = sz - 1`).
- Result: `luby_m_bounds` (`1 ≤ luby_m i ≤ i + 1`, a power of 2, for every `i`), `luby_m_budget`
  (`0 < 100 * luby_m i < 2^64` for `i < 2^57`, covering the counter range `< 2^20 + 1`),
  `luby_m_shift` (final `seq < 64` for `i < 2^63`), `luby_m_first_values` (`1,1,2,1,1,2,4,1,1,2`,
  by `eval`).
- Deliverable 3 done in full: `luby_rec` (the standard recursive definition with the least `k`,
  termination via `luby_level`/`luby_least`) and `luby_m_luby_rec: luby_m i = luby_rec i` for
  every `i`.
