# 2026-11-18 — feature session (issue #36: simplifying Tseitin gates, part of #26)

- `core/src/lib.rs`: the Tseitin gates are now `tseitin_and/xor/ite`; `gate_and`, `gate_xor` and
  `gate_ite` simplify first and only fall back to them otherwise. An input on variable 0 is a
  constant; two inputs on the same variable are equal or complementary. `gate_ite` also turns a
  constant data input into an `and`/`or` gate and `ite(c, x, ¬x)` into `¬(c xor x)`. `gate_or`
  is still `¬and(¬a, ¬b)`. `urust/` regenerated (0 placeholders, no new stubs, `check-spec.sh` ok).
- Proofs: `QFBV_Defs` gives the models `and_t/xor_t/ite_t` (Tseitin) and `and_m/xor_m/ite_m`
  (simplifying, mirroring the Rust). In `QFBV_Circuits`, the old gate lemmas are now
  `and_t_ok` etc. The new `and_ok`/`xor_ok`/`ite_ok` keep their statements, proved by case
  analysis (`lit_sem_var0`, `lit_sem_same_var`). A gate now adds *at most* one variable, so every
  exact variable count (`*_fst`, `*_count`, `mulc`/`mulr`, `dr_counts`) became a monotonicity
  fact. In `QFBV_Refine`, the gate contracts require `fst (fst (and_m s a b)) < 2^64` (the model's
  own count) instead of `Suc (fst s) < 2^64`. Each loop proof gets its per-step bound from
  `foldl_upt_count_mono` (a step's state is at most the final state) via `*_step_lt` lemmas. These
  lemmas are stated in exactly the shape that crush leaves: the numeral 18446744073709551616 and
  the folded `foldl` form, because simp does not match `2 ^ 64` against the numeral. `bok`'s
  Ite clause now states the `ite_vec_m` count. `check_sat_correct` and `spec/` are unchanged.
- Suite `QF_BV_Smt-2026-11-18` (30 s, 8 GB, 4 jobs; main was re-run under the same conditions):
  main 32/101, PAR-2 4180.5 s; this change **44/101, PAR-2 3427.3 s**, no instance lost, no wrong
  answer or bad model. Total time 2055.2 s → 1663.0 s; on the 32 instances both solve,
  40.5 s → 7.2 s. The three `brummayerbiere4` out-of-memory crashes remain: their 1024-bit
  `bvudiv` multiplies fresh quotient/remainder vectors, where no input is constant.
- Pitfalls: `isabelle-devcopy` deletes everything in `dev/`, so keep logs and scratch builds
  elsewhere (`target/`). Under load, the Pool Server re-checks `QFBV_Refine` in about 20 min. A
  batch `isabelle-check` lists every error at once and was faster for this file.
