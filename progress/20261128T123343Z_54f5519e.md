## The variants (uRust subset)

- **(a) Target phase (CaDiCaL / Kissat).** `nc` is the trail length after the last propagation
  that found no conflict (CaDiCaL's `no_conflict_until`). At every backjump (both the learning
  one and the chronological one), if `nc > tsize` the signs of `trail[0..nc]` are written to
  `tph: Vec<Option<bool>>` and `tsize = nc` (CaDiCaL's `update_target_and_best`). After that,
  `nc` is lowered to the backjump position. A new helper `copy_phases(tph, set, trail, nc)` first
  clears the variables it recorded last time (`tset`), so each update costs O(old + new trail),
  not O(n). A decision takes `tph[v]` if it is `Some`, else the saved phase `ph[v]`. At a restart
  the target is cleared (`tsize = 0`), so it is "the largest conflict-free trail since the last
  restart", as the issue says.
- **(b) Best phase + rephasing (CaDiCaL).** `bph`/`bset`/`bsize` are kept like the target, and
  also updated at a restart. At a restart with `total ≥ next_rephase`, `rephase(ph, &bph, k)`
  resets the saved phases following CaDiCaL's schedule for stable mode without local search:
  O (all true, our initial phase), I (all false), then (B, O, B, I) repeated. B copies the
  recorded best phases and leaves the other variables alone. The best phases are then cleared
  (CaDiCaL resets `best_assigned` at each rephase, so "best" covers the time since the last
  rephasing, not the whole run). Interval: `next_rephase = total + 1000·(k+1)` (CaDiCaL's
  `rephaseint` = 1000, arithmetic growth). Rephasing happens only at restarts, which already
  backtrack to level 0. Counter `rephased < 2^20`, like `restarts`.

All parameters are CaDiCaL defaults; none was tuned on an instance. Restarts stay Luby·100 (no
stable/focused mode switch). CaDiCaL uses target phases only in stable mode; here they are always
on.

## Proof obligations for a later `dpll` contract (compared with #108 / #124)

Neither variant changes the clause database, the watches, the reasons or the trail structure.
They only choose the sign of a decision literal (and, at a restart, the saved phases). So the
list of #108/#124 is unchanged, and the decision step reuses #69's fact that a decision of either
sign on an unassigned variable keeps the invariants. New, all of them local:

- **(a)** `tph` has length `n` (it is only written through `copy_phases`, which writes only
  under `v < length tph`). The decision reads `tph[v]` for the `v` returned by `heap_pick`,
  which is `< n` already (the same bound #69 uses for `ph[v]`). No fact about `tset`'s contents
  is needed: `copy_phases` guards every index. `nc`, `tsize` ≤ `length trail`-style bounds are
  not needed for safety either (`copy_phases` stops at `trail.len()`). There is no overflow:
  `nc`, `tsize` ≤ `trail.len()` ≤ n.
- **(b)** `bph` likewise; `rephase` keeps `length ph` (writes only under `i < length ph`,
  reads `bph` under `i < length bph`). Overflow: `rephased < 2^20` (in the guard) bounds
  `1000·(rephased + 1)`, but `next_rephase = total + …` adds to `total`, which already needs the
  bound of #108 (`total` is unbounded in the contract; bound it like `restarts` or use
  `saturating_add`). Fuel `3 ^ n`: unchanged, the restart branch is the same shape.
