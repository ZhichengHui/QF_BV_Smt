## The variants (uRust subset)

- **(a) LBD update (Glucose).** `analyze` also returns `used`: the conflict clause `cf` and every
  reason `rs[i]` it resolves with. Before the backjump (all their literals are still assigned),
  `update_lbd` recomputes with `clause_lbd` the LBD of each learned clause in `used` whose LBD is
  above 2, and keeps the new value if `new + 1 < old`. That is Glucose's rule (`nblevels + 1 <
  c.lbd()`), taken as is. `clause_lbd` now runs several times per conflict, so its stamp is a
  separate counter `stamp` (incremented before each call) instead of `total`. Switch:
  `LBD_UPDATE`.
- **(b) Tiered retention (CaDiCaL).** A flag `uflag[c − m0]` per learned clause: set when the
  clause is learned and when it is in `used`. In `reduce_db`, a clause with LBD ≤ `TIER2` = 6 (CaDiCaL's
  `tier2` default) and the flag set is not a candidate: it is kept, like the clauses of LBD ≤ 2
  (tier 1, kept forever) and the reasons. The remaining candidates (the local tier, and tier-2
  clauses unused since the last reduction) are halved as before (lowest LBD, then newest).
  Every kept clause has its flag cleared, so a tier-2 clause has to be used again to survive
  the next reduction. CaDiCaL uses a small counter instead of a single flag, so a tier-2 clause
  survives one or two unused rounds; here it is one. Schedule (2000 + 300·k) and halving are
  unchanged from #108.

The parameters are the published defaults (Glucose's update condition, CaDiCaL's tier limits
2 / 6); none was tuned on an instance.

## Proof obligations for a later `dpll` contract (compared with #108)

The list of #108 (prefix `cs`, entailment, `dstate`, reasons, watches, `WP`/`WS`, bounds, fuel)
is unchanged: neither variant changes which clauses `db` holds or how the watches are rebuilt,
only which learned clauses `reduce_db` keeps. The kept set is still a sub-list that contains the
originals and every locked clause, and that is all the #108 argument uses. New:

- **(a)** `update_lbd` writes only `lbd`, in place, so `length lbd = length db − m0` is kept.
  It indexes `db[c]` only under `m0 ≤ c ∧ c − m0 < length lbd`, so that invariant alone gives
  `c < length db`; no fact about `used` is needed (the contract of `analyze` gets one more
  output, with no property required). `clause_lbd` still guards `mark` by its length.
  **Overflow:** `stamp += 1` runs up to `1 + |used|` times per conflict, and the number of
  conflicts has no bound in the contract (as for `total` in #108, which was the stamp before).
  For a contract, either bound it like `restarts < 2^20`, or use `wrapping_add`/`saturating_add`. With
  either, a reused stamp only makes an LBD come out too small, which correctness does not
  depend on.
- **(b)** One more vector `uflag` with `length uflag = length lbd`: it holds because it is pushed
  together with `lbd` and `reduce_db` builds `uf2` together with `lbd2`. The marking loop in `dpll` is
  guarded (`u1[k] − m0 < length uflag`). In `reduce_db`, the extra conjunct only shrinks the
  candidate set, so `acc ≤ quota` and `left = quota − acc` stay as before.
- Fuel `3 ^ n`: unchanged; neither variant touches the trail or `lim`.

## Recommendation

Stack **(a)+(b)** (`a49260e`) after `7043c52`, once Rust can merge (#64 / PR #72). It is the best
PAR-2 in all three rounds (−36 s), loses nothing, uses only published defaults, and adds two
vectors whose only obligations are length invariants (plus the stamp bound, which `7043c52`
already needs for `total`). (a) alone is a close second on the instances other than
tcas60_k_0, but costs bench_1784 12 s. Since one order-sensitive instance makes the difference
between them, a planner should treat the margin as uncertain and confirm it on a larger suite
(#67). bench_9019 needs something else; for sat instances phase handling (target / best phases,
CaDiCaL/Kissat) is the natural candidate, not clause retention.
