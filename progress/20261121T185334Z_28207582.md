## What verification would need

- (a') decision heap + phase saving. New state: `act`, `heap`, `hp` (`Vec<usize>`), `ph`
  (`Vec<bool>`), `inc` (integer activity, `inc += inc / 20` per learned clause; at `2^40` every
  activity and `inc` are shifted right by 30 and the heap is rebuilt; bumps saturate at
  `usize::MAX`). None of it enters `cinv`: the heuristic only chooses the decision variable and its
  sign. Proof obligations: (1) `heap_pick` returns an unassigned variable or `None` only when every
  variable is assigned — needs a heap invariant "every unassigned variable is in the heap"
  (`hp[v] = MAX` ⟹ assigned; `heap_back` re-inserts every unassigned trail entry); the heap order
  itself is not needed for correctness, only `hp`/`heap` being inverse permutations on the
  elements in the heap and in bounds; (2) `cinv_decide` assumes a positive decision
  (`¬ Lit_neg l`, `a[v := Some True]`); it and `dstate_decide`/`wstate_decide` need generalising
  to either sign. `analyze`/`analyze_clause` get `act`/`inc` threaded through; their contracts
  must say `seen`/`learned`/`cnt` are unchanged by it (the `analyze_ok` proof only gains a frame
  condition). Termination: `heap_pick` pops at most `heap.len()` times; heap operations are
  bounded by the heap depth. The measure and `dpll_fuel = 3 ^ n` are unchanged. Floats are not
  used.
- (b') restarts. New state: `conflicts`, `restarts`, `budget` (`usize`), `luby`. A restart is a
  backjump to level 0 that pushes nothing: the trail is cut to `lim[0]`, `lim = []`, `q = lim[0]`.
  `cinv` holds (it is `cinv_backjump`'s cut without the learned clause: `take 0 L`, `take (L!0) t`,
  `take (L!0) rs`; the trail below `L!0` is already propagated, so `wstate` holds with `q = L!0`),
  but the measure `meas` decreases. Restarts are bounded by `restarts < 2^20`, so the iterations
  are at most `(2^20 + 1) * 3 ^ n` (lexicographic: restarts left, then `meas`); `dpll_fuel` becomes
  `(2^20 + 1) * 3 ^ n` (it is in `proof/QFBV_Proof.thy`, not `spec/`: the top-level theorem
  quantifies over the fuel). Restarts happen only while `learn` is true, as analysis needs reasons.
- (c) normalization. It is a new pass `normalize` between `lower_problem` and `elim`; it keeps the
  variables and their widths, so the model needs no reconstruction: its contract is that the
  result is well-sorted and has the same models as its input (`eval_defs`/`core_sem` of each new
  definition equals that of the old one it replaces, in every model of the assertions). The
  substitution `v := t` is sound because it applies only to occurrences `Var(v)` other than the
  one in the assertion `v = t`, and only after the definition of `t` (index `b < j`), so it is
  acyclic; by induction on the index, in every model of the (kept) assertions each new definition
  has the value of the old one. Translation: the prototype uses `HashMap`, `format!` (`Debug` for
  the key), `iter().all`, closures and `vec![None; n]` of tuples, which add external stubs
  (`Box::new_uninit`, `write_box_via_move`, `Iterator::all`, ...) and new locale prisms (`Norm`,
  `fmt_Formatter`, `bool list`, `(… option) rvec`) — it is not in the subset as written. A subset
  version needs the definition lookup without hashing (linear search, or a sorted index of keys
  over `usize` tuples: definitions are shallow, one operator over references), loops instead of
  iterators, and no `fmt`.
- Translation of (a')/(b') (front end `236538c`, into `scratch/`, not `urust/`): 0 placeholders,
  templates and locale identical to the unmodified prototype's, after the cleanup `4ff5ec3`
  (explicit saturation instead of `saturating_add`, which is an external stub; the unused linear
  `pick` removed, it added an `Option<usize>` prism; the heap code placed below `read_model`, as
  its `Vec<usize>` otherwise renumbers the prisms — the same pitfall as `propagate_pass`). Before the
  cleanup: 0 placeholders but one new stub and a changed locale. (c): 0 placeholders but new stubs
  and prisms, as above.

## Proposed decomposition (for a planner, after #65)

1. Decision heap + phase saving (a') in `dpll`, with contracts: heap module (`heap_up`, `heap_down`,
   `heap_insert`, `heap_pop`, `heap_pick`, `heap_back`, `heap_bumped`, `heap_rebuild`) and its
   invariant; `cinv_decide` for either sign; `analyze` with `act`. Expected: 78 → 91.
2. Restarts (b') on top of 1: restart step lemma (`cinv` after the cut), measure
   lexicographic with the bounded restart counter, `dpll_fuel` × (2^20 + 1). Expected: → 93–94.
3. Word-level normalization (c) in the subset: hash-free sharing with commutative order, `x = x`,
   `x + ~x`, `x * ones`, flattened sorted products, substitution of `v = t`; semantic-equivalence
   contract. Expected: → 96 with 1 and 2. Worth checking whether the sharing can keep the
   prototype's variable order (to avoid the two losses), and whether distributivity (distrib64)
   is worth one more rewrite.
