## Patterns that work (rvec contracts)

- `crush_base simp add: <lots of arithmetic lemmas>` is what makes these proofs take 5–25+ min or
  not terminate. Give `crush_base` only the definition of the result predicate (`cnfv_res_def`,
  `cnf_res_def`, `low_res_def`) and cheap facts; put `unat_*`, `word_less_nat_alt`,
  `unat_word_Suc_simp`, `antisym_conv` into a following `auto`. `antisym_conv`/`unat_word_Suc_simp`
  inside `crush_base` were the worst.
- `st_of_simps [simp]` splits `st_of c` into `(unat (Cnf_num_vars c), vecs_of ...)`, so folding
  equations stated over a state variable `s` (`dr_fold`) do not match. Use them instantiated and
  simplified: `dr_fold[where s=\<open>st_of c\<close>, simplified]` (and `dr_lt[..., unfolded divrem_m_dr
  room_def, simplified]`). A precondition `st_of c = s` does not help: crush substitutes `s`.
- Nested loops: after the outer `crush_base`, the inner-loop entailment is one goal among pure
  ones; find it with `prefer k apply (match conclusion in \<open>_ \<longlongrightarrow> _\<close> \<Rightarrow> \<open>-\<close>)`, move it
  last with `defer k`, close the pure ones with `auto ...[n]`, then `subgoal for ...` (the names of
  the parameters change when the simp set changes: re-read them).
- `lst_of_eq [simp]` splits the IH's `lst_of aa = X` into field equations, so a later `lst_of aa`
  is not rewritten; `auto simp add: lst_of_def` afterwards puts both in the same form.
- Working with the Pool Server on these files: `supply [[crush_warn_at_full_blown_clarsimp = false,
  goals_limit = 1]]` keeps candidate output small; `isabelle_goal` ignores `goals_limit`, so query a
  tiny line (a `section`) to sync and see `still_running`. A file is only re-checked when a tool
  touches it, and a session idle for ~10 min is reaped (the next query re-checks the whole file):
  poll every few minutes. Experiments go faster in a copy with every other proof replaced by `sorry`
  (a script in the session's scratch dir did this); prefixes of `QFBV_Refine` take minutes.
