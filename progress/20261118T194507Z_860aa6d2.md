# 2026-11-18 — feature session (issue #35: iterative DPLL over a trail, part of #26)

- `core/src/lib.rs`: the recursive DPLL is replaced by an iterative search over a trail. The
  assignment is updated in place; `trail` lists the true literals in order and `lim` the trail
  positions of the decisions (MiniSat-style `trail_lim`, so the decision level of an entry is the
  number of decisions at or before it). `propagate_pass`/`propagate` push implied literals on the
  trail and return the state also on a conflict; `backtrack` pops the trail to a position and
  unassigns; on a conflict the last decision is undone and its negation pushed (chronological
  backtracking). `dpll(cs, n)` now takes the number of variables. `read_bits`/`read_model` moved
  before `dpll` so that the generated prisms change as little as possible.
- `urust/` regenerated (0 placeholders, no new stubs). The generated locale swapped two prisms
  (`(64 word) list` now comes before `CoreTerm list`, from the new `lim`); the locale `QFBV_heap` in
  `spec/QFBV_Spec.thy` was updated to match (the one allowed change of `spec/`).
- Proofs (`proof/QFBV_Dpll.thy`, rewritten DPLL part): trail invariant `tr_ok`, entailment of
  implied entries `tr_imp`, state invariant `dstate`, pass model `tpass_m`. Termination of the
  search loop: `meas` reads the trail as a base-3 number (digit 1 for a decision, 2 for an implied
  entry); every iteration increases it and it stays below `3 ^ n`. The contract `dpll_top_contract`
  gives `None` only for unsatisfiable clauses (now: no model at all) and otherwise a total
  satisfying assignment. Fuel: the search loop needs `3 ^ n < urust_fuel` (n = CNF variables);
  `QFBV_Proof` defines `dpll_fuel` and adds it to the fuel of `solve_core_spec`, `solve_spec`,
  `solve_correct` (N = size_bound + dpll_fuel + 1) and `QFBV_Top.fuel_top`. `check_sat_correct`
  unchanged. `isabelle-check`: EXIT 0.
- Benchmark `QF_BV_Smt-2026-11-18` (both binaries run in this session, load ~15-30 on 64 cores):
  main 32/101, PAR-2 4182.9 s, total 2059.8 s; new 32/101, PAR-2 4185.2 s, total 2060.6 s; same
  instances solved, no wrong answers or bad models. Time on main's solved instances: main 42.9 s,
  new 45.2 s (within noise; repeated runs of the two largest show ~3 % either way).
  **The aim (less time) is not met**: callgrind on `sage/app1/bench_198` shows 96 % of the time in
  `propagate_pass` (82 % in `clause_status`); the assignment clone was negligible. Per call of
  `propagate` the solver scans all clauses ~1.5 times (bench_7314: 244k calls, 375k passes; bench_198:
  one call with 112 passes). A cyclic scan that stops after a full round without assignment was
  tried and gave no gain either (reverted). The gain must come from propagation that visits only the
  clauses of the newly assigned literals (occurrence lists or watched literals over the trail), which
  this trail now supports (the trail is the propagation queue).
- Pool Server notes: its heap builder only stacks on HOL (no AutoCorrode parent), so no task heap;
  `vec_pop` needs `inline: vec_pop_def` in `crush_base`.
- Left: `pass_m` in `proof/QFBV_Defs.thy` is now unused (harmless; can be removed).
