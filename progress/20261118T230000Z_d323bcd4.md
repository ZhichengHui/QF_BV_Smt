# 2026-11-18 — feature session (issue #44: verified word-level evaluator, part 1 of #43, part of #26)

- Claimed #43 (unconstrained-term elimination). Looked at `brummayerbiere4/unconstrained06,07,10`:
  each needs `=` with one unconstrained side whose other side is a nested 1024-bit `bvudiv` of
  variables that occur twice, so model reconstruction must *evaluate* that side. The solver had no
  evaluator (constant folding through `blast` fails for division, which introduces fresh
  quotient/remainder variables). Decomposed #43 into #44 (this evaluator) and #45 (elimination,
  dead-code removal and verified model reconstruction, `depends-on: #44`); #45's body records the
  design worked out here (keep variables, definition count and every definition width unchanged so
  that `csize_bound` and `fuel_bound_lt` carry over; free definitions form trees; reconstruction
  in increasing order of tree tops).
- `core/src/lib.rs`, new section "Evaluation of core terms": `eval_term` (recursive, like `blast`)
  and `eval_defs` (all definitions of a problem), with bit-list helpers `bits_not`, `bit_op`,
  `bits_bitwise`, `full_add`, `bits_add`, `bits_shift_const`, `bits_mul` (shift-add),
  `bits_eq`, `bits_ult`, `bits_zext`, `bits_shl1`, `bits_divrem` (restoring long division with a
  remainder one bit wider than the operands, from the top bit down; divisor 0 gives all ones and
  the dividend), `shift_amount_step` and `bits_shift` (the shift amount is computed from the top
  bit of `b` down and capped at the width),
  `bits_extract`, `bits_concat`, `eval_bin`. Not called by `solve` yet. `urust/` regenerated
  (0 placeholders, no new stubs, locale unchanged). Tests: `core/tests/eval.rs` (all twelve
  operators against machine arithmetic for widths up to 64, `not`/`extract`/`ite`/references,
  1024-bit division checked by `q * b + r = a`, `r < b`, and division by zero).
- Proofs, `proof/QFBV_Eval.thy` (session `QFBV_Proof`, imported by `QFBV_Proof.thy`): functional models (`bnot_m`, `bbitw_m`,
  `badd_m`, `bmul_m`, `bdivrem_m`, `bshift_m`, ..., `eval_m`, `eval_defs_m`); `eval_m_correct`:
  for `cwt ws ds t` with `ws`, `ds` the lengths of the values, the result has length
  `cwidth ws ds t` and `bits_nat` of it is `ceval ws ds (map bits_nat vs) (map bits_nat dv) t`;
  `eval_defs_m_correct` gives `cdef_widths`/`cdef_values`. Contracts: every Rust function
  computes its model; `eval_term` needs fuel `size t + 1` and `eok` (well-sorted, every subterm
  width `w` with `2 w + 2` at most the fuel and below `2^64`); `eval_defs` needs `edefs_ok`.
- Pitfalls: loops that index with `len - 1 - j` leave checked-subtraction goals that `crush`
  does not close; count down instead (`while i > 0 { i -= 1; ... }`, `unat_dec`), and state the
  fold-step lemmas in simp's normal form (`Suc n - i`, `i - Suc 0`). Word arithmetic such as
  doubling a counter goes into a tiny helper function whose contract is proved by hand
  (`goal_cases`, then `crush_base` with the derived `unat` facts). For a recursive function whose
  model has an `if` (here `Ite`), keep the term abstract in that case so that `goal_cases`
  exposes the precondition before `crush_boot` splits.
- Pitfalls: short-circuit `&&`/`||` and `if`s on bits inside a loop body make `crush_base` split
  into many branches (a loop step ran > 10 min); factor per-bit logic into tiny functions
  (`bit_op`, `full_add`) and keep their models opaque (`fa`) in the loop invariants. `step` is an
  outer-syntax keyword (do not name a fact `step`). For a long theory, put the checked prefix
  into a task heap and continue in a small file on top; a batch `isabelle build` of that small
  session runs the contract proofs in parallel and is much faster than the Pool Server, which
  checks `apply` proofs one after the other.
- Pitfall: `isabelle-check` (and CI) only load the theories reachable from `QFBV_Top`; a theory
  that is only listed in `proof/ROOT` is not checked. Import a new theory from one that the top
  level imports (here `QFBV_Proof.thy`) and confirm it in the check log
  (`theory QFBV_Proof.QFBV_Eval`).
