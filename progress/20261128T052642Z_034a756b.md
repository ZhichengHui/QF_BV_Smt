## The variant (uRust subset)

- **LBD when learned.** `clause_lbd` counts the distinct decision levels of the learned clause
  before the backjump. The level of a literal is `level_at`: a binary search of its trail position
  in `lim`. Levels are marked with a per-level stamp vector (`lmark`, length `n + 1`), and the
  stamp is the conflict count. `dpll` keeps `lbd[c - m0]` for every learned clause `c`; `m0` is
  the number of original clauses.
- **When.** While learning is on, right after a propagation without conflict, once the total
  number of conflicts reaches `next_reduce`. The first reduction comes at 2000 conflicts, and each
  later one comes `2000 + 300·k` conflicts after the one before (the k-th). Deletion runs at any
  decision level, not only at restarts: the Luby runs grow to tens of thousands of conflicts, so
  waiting for a restart would delay it too much.
- **What is kept.** All original clauses (unchanged, in order, a prefix of `db`). Every learned
  clause of LBD ≤ 2, and every clause that is the reason `rs[j]` of a trail entry (locked). Of
  the remaining learned clauses, half are kept: a histogram over LBD picks a threshold `t`; all
  clauses with LBD < `t` stay, and with LBD = `t` the newest ones stay until the quota is met.
  This takes O(clauses), with no sort (the only sort in the crate is an insertion sort).
- **Watches.** The kept clauses keep their watched positions (`pos`). The lists (`next`, `head`)
  are rebuilt from those positions, and the reasons `rs` are renumbered by the map from old to new
  index. The reduction runs only when no conflict is pending and the whole trail has been
  propagated (`q = trail.len()`), and the watch invariant is a property of each clause. So it
  still holds for the kept clauses, and no propagation needs to be redone.
- **Ranking: LBD.** LBD is the standard measure (Glucose, CaDiCaL's tier 1/2), and it predicts
  well which clauses will be used again. It costs one pass over a clause when it is learned, and
  nothing during propagation. Activity would need a bump per clause in `analyze` and a rescale,
  which means more state for a later contract. Length is a weaker predictor on these CNFs, where
  learned clauses average 68–238 literals (see the progress entry of #81).

## Proof obligations for a later contract

For the state of `dpll` (`cinv` in `QFBV_Cdcl.thy`, `wstate` and `wl_ok` in `QFBV_Watch.thy`), a
reduction `db ↦ db'` keeps:

- **`∃ls. db = cs @ ls`.** The originals are the prefix `take m0 db`, copied unchanged, and the
  kept learned clauses are a sub-list of `ls`.
- **Entailment.** `∀σ. cnf_sem σ cs ⟶ cnf_sem σ db'` holds because `set db' ⊆ set db`. The
  converse also holds, because `cs` is a prefix of `db'`. So `cs`, `db` and `db'` have the same
  models.
- **`dstate db' n a t L`.** `tr_imp db t j` becomes `tr_imp db' t j` by `tr_imp_mono`, applied with
  `cnf_sem σ db' ⟶ cnf_sem σ cs ⟶ cnf_sem σ db`. This step needs the equivalence above, not only
  the subset: a smaller clause set has more models.
- **Reasons** (`lr ⟶ reason db t j (rs ! j)`): every `rs ! j` is locked, so it is kept, and
  `db' ! map(rs ! j) = db ! (rs ! j)`. Hence `reason db' t j (map (rs ! j))`. The positions of
  decisions have `rs = 0`, which is an original clause; they are renumbered by the same map.
- **Watches** (`wl_ok`, `lends`, `length h = 2n`). The lists are rebuilt over the new `pos` with
  `head` of the same length, and every list ends in `2^64 − 1`. `wl_lists` needs a lemma that
  pushing each slot at the head of its literal's list builds `Ls` with `lseg`/`distinct`. It is
  the same argument as `watch_init`, but with the positions `pos[2c]` and `pos[2c+1]` instead of
  `0, 1`; the distinctness `p ! 2c ≠ p ! (2c+1)` carries over.
- **`WP db' p' t k` for every `k ∈ set L`, and `WS` on the propagated prefix.** `WS` is a
  statement about each slot: `wlit db' p' s' = wlit db p s` and `oth s' ↦ oth s` under
  `s' = 2·map(c) + i`. So each slot of a kept clause inherits it, and the slots that are gone
  carry no obligation. The same holds for `SP db' t` and `SP db' (take k t)`, since `set db' ⊆ set db`.
- **`0 < length db'`, `length db' < 2^62`, `dpll_wf n db'`.** `db'` is no longer than `db`, contains
  the nonempty prefix `cs` (the case `m0 = 0` needs `0 < length cs`, as now), and each of its
  clauses is in `db`.
- **LBD state.** Nothing depends on `lbd` or `lmark` for correctness: `length lbd = length db − m0`
  is needed only for safe indexing. `clause_lbd` indexes `mark` only below its length (a guard),
  and `level_at` needs no invariant.

**Fuel `3 ^ n`.** `meas n (length t) L` depends only on the trail and the decision positions. The
reduction changes neither, and it runs in an iteration that then makes a decision (or returns), so
that iteration still increases `meas` as before. Termination does not use the size of `db` at
all: learned clauses do not enter the measure. They only need a bound for the indices, and
`length db < 2^62` (learning only while `db.len() < usize::MAX / 4`) still holds because deletion
only shrinks `db`. One change: "learning stops for good at `usize::MAX / 4`" is no longer
monotone, since `db` can shrink, but neither the measure nor `cinv` uses that. The restarts of
`8945699` already need their own bound outside `3 ^ n` (`restarts < 2^20`; a restart lowers
`meas`), and deletion adds nothing to it.
