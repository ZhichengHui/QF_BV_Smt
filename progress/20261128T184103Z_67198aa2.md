## Pitfalls found (for the `dpll` proof)

- `ana_loop`'s equations are unconditional simp rules that unfold without end on a symbolic
  position, so `crush_base` did not terminate. `ana_at` hides it, with `ana_step` and `ana_stop`.
- An index write into a vector held in a reference (`learned[0] = …`), inside a loop or on a local
  `let mut l = v` copy, leaves a guarded goal: `‖ ln' = ln ‖` in the loop, or a non-pattern
  schematic `‖ ad = ?y … ‖` that neither `refl` nor `hd_Cons_tl` resolves. Writes on a
  by-value parameter (`second_watch`, `set_first`) prove directly. Rewriting the Rust was cheaper
  than fighting it.
- Each change of `core/src/lib.rs` changes `QFBV_Funs`, so the task heap (AutoCorrode +
  theories up to `QFBV_Dpll`, `target/heap65`) has to be rebuilt: about 7 minutes.
- Implications inside a loop invariant (`P ⟶ Q` with quantifiers) made `crush_base` slow. Make
  such facts preconditions and keep the invariant free of implications.
